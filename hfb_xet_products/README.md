# XET Products – XML product import/export (`hfb_xet_products`)

Imports products from an XML file fetched over SFTP and periodically exports products to XML, generated from an XET template, to configured recipients over SFTP. The module builds on XET Base (`hfb_xmlmap_exporter`): it registers a new provider type and runs every import or export as one `communication.log` record. XET Base itself is not modified.

## Features

- **Channels** (`communication.provider.xet_products`): one record per import source or export recipient, each with its own SFTP connection (password or Ed25519/ECDSA/RSA key, optional SHA256 host key fingerprint). A matching `communication.provider` record of type `xet_products` is created automatically.
- **Import** `fetch → parse → apply → images → finalize`:
  - fetches a file matching the channel pattern; with an archive directory the oldest file is taken, without it the newest one; files are never skipped, even if imported before,
  - streams `<Product>` elements with `lxml.iterparse` into staging lines (`xp.staging.line`),
  - matches products by **SKU + EAN** (`product.product.default_code` + `barcode`): updates only changed fields or creates a new product; one savepoint per line, so a failing line does not stop the run,
  - optionally downloads the "main photo" media URL into `image_1920`, only when the URL changed; download errors are recorded on the line,
  - moves the remote file to the archive directory (or to the error directory when fetch/parse fails).
- **Export** `select → generate → send → finalize`:
  - full or incremental selection (product or media `write_date` after the cut-off of the last accepted run),
  - XML generated by `xml.export.template.generate_xml` with the run log as the start record,
  - post-processing: no namespaces, CDATA for template nodes with `as_cdata`; optional XSD validation,
  - atomic upload: `<name>.part` then rename, remote size check.
- **Run control**: at most one pending/running run per channel (partial unique index), atomic stage lock, recovery of stages locked longer than the configured timeout, retries with delay, imports processed before exports, exports wait while an import of the same company is running.
- **Product data**: 50+ PIM fields on `product.template` (`xp_*`), media links (`xp.product.media`) typed by an editable dictionary (`xp.media.type`).

## Data model

| Model | Purpose |
|---|---|
| `communication.provider.xet_products` | Channel configuration (import or export) |

## Workflow

### Run result (`communication.log.xp_result`)

```
pending ──acquire──> running ──next stage──> pending ... ──finalize──> accepted | manual
                        │                                   
                        ├── no file / no products ──> nofile
                        └── fatal error / attempts exhausted ──> error
```

| Value | Label |
|---|---|
| `pending` | Waiting |
| `running` | Running |
| `accepted` | Finished |
| `manual` | Finished with line errors – to review |
| `nofile` | Nothing to process |
| `error` | Error |

### Scheduled actions

| # | Name | Model | Method | Default interval |
|---|---|---|---|---|
| 1 | XET Products – initialise import runs | `communication.provider.xet_products` | `_cron_xp_init(direction="import")` | 1 hour |
| 2 | XET Products – initialise export runs | `communication.provider.xet_products` | `_cron_xp_init(direction="export")` | 1 day |
| 3 | XET Products – process runs (worker) | `communication.log` | `_cron_xp_process()` | 1 minute |

All three are inactive after installation.

## File format

Root `<Document>` without namespace, repeated `<Product>` with 55 single-value elements and the `<Product_images><img url="…" size="…"/></Product_images>` collection. The element-to-field mapping is defined in `models/xp_parser.py` (`FIELD_SPEC`, `MEDIA_SPEC`) for import and in `data/xet_template_products.xml` for export. Required on import: `SKU`, `EAN`, `Product_name`.

## Configuration

1. Install `paramiko` on the server (`requests` and `lxml` ship with Odoo).
2. *XET Provider → 🦺 Konfiguracja → Konfiguracja Dostawców → Provider XET Products*: create an import channel (input, archive and error directories, file pattern, data language, main photo download) and one export channel per recipient (output directory, XET template `xet_template_products`, full or incremental mode, product filter, file name).
3. Use **Test connection** and copy the reported host key fingerprint into the channel if host verification is required.
4. Activate and schedule the three cron jobs.
